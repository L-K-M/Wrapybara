# k3.md — Wrapybara, a second full review

A fresh, full read of the repository (~10k lines of Swift across `Wrapybara/` and

and the screenshot), done **after** the glm review (`glm.md`) and its curated backlog

## 1. Executive summary

The codebase is in genuinely good shape: the pure-core/effects-at-the-edges
discipline holds everywhere I looked, the comments are honest, and the tests cover
the decidable parts well. The first review was thorough — I verified each of its
findings and found no false positives worth retracting.

What it missed is mostly in three clusters:

1. **The find bar** — it beeps on every non-matching keystroke, Esc doesn't close it
   (the `cancelFind` action exists but is wired to nothing), and the ⌘G repeat path
   is unreachable when the bar is hidden. Three small papercuts in one of the most
   used surfaces.
2. **Zoom handling in the runtime** — the marquee feature (edit a boost in
   Wrapybara, watch the running app restyle) silently resets the user's page zoom to
   the configured default on *every* live configuration apply. Zoom is also never
   persisted, despite a doc comment claiming ⌘+/⌘− "writes back" to the setting.
3. **A handful of one-file quality issues** — bare-letter keyboard shortcuts that
   fire on ordinary typing, non-square artwork squashed into square icons, the
   Settings sheet shelling out on the main actor, nonsense suggested names for IP
   hosts.

Plus the two biggest *missing* pieces both reviews agree on — a real error page and
a visible loading state — which this pass implements (they're small, and they're the
most user-visible gaps in the runtime).

## 2. Bugs

### 🐛 K1 · P1 · 🆕 — live boost editing resets the user's page zoom
`SiteWebController.apply(_:)` runs on every live configuration change (that's the
"drag a slider, the app restyles" feature) and unconditionally executes
`webView.pageZoom = newConfiguration.wrap.behavior.pageZoom`. So: zoom into an
article with ⌘+, then touch *any* boost knob in Wrapybara — the page snaps back to
the configured zoom. Every keystroke in a boost text field does it again. The same
line re-sets `customUserAgent` even when unchanged (harmless, but the same fix
covers it). **Fix:** compare old and new behavior; only push `pageZoom` /
`customUserAgent` to the web view when that specific value changed.
🚧 Implemented this pass.

### 🐛 K2 · P2 · 🆕 — the find bar beeps on every keystroke that doesn't match
`FindBarController.find` ends with `if !result.matchFound { NSSound.beep() }`, and
incremental search calls it per typed character. Typing a word whose early prefixes
don't match ("zephyr" — no "zeph") beeps once per keystroke. Safari beeps *never*;
it styles the field. **Fix:** only beep for an explicit repeat (⌘G/⇧⌘G), never for
`fromUserTyping`. 🚧 Implemented this pass.

### 🐛 K3 · P2 · 🆕 — Esc doesn't close the find bar; `cancelFind` is dead code
`SiteWindowController.cancelFind(_:)` exists and hides the bar, but nothing calls
it: no menu item, no key equivalent, no field hook. Pressing Esc in the find field
does nothing (it may beep). **Fix:** make the find bar its search field's delegate
and hide on `cancelOperation:` — field-scoped, so it never steals Esc from the page
(important: a page-modal or a lightbox expects Esc to reach the page). 🚧
Implemented this pass.

### 🐛 K4 · P2 · 🆕 — bare-letter keyboard shortcuts fire on ordinary typing
Two buttons use unmodified letter shortcuts:
- `LibraryView` empty state: `Button("Wrap a Site…").keyboardShortcut("n")`
- `WrapEditorView` Build button: `.keyboardShortcut("b")`

On macOS these fire whenever the window is key and no control consumes the key —
press "b" after clicking the wrap icon and an unrequested build starts; press "n"
with the library focused and the New Wrap sheet pops open mid-thought. The menu bar
already provides real ⌘N / ⌘B. **Fix:** drop both (`.defaultAction` is also wrong
here — these aren't dialogs). 🚧 Implemented this pass.

### 🐛 K5 · P2 · 🆕 — non-square artwork is squashed into the icon
`IconComposer.compose(artwork:style:plateColor:)` draws the artwork into a square
destination rect regardless of its aspect ratio, and `redraw(_:edge:)` (the `.asIs`
style) does the same. Any wide or tall image — a user-chosen file, or the
`og:image` fallback — comes out visibly distorted on the plate. **Fix:** compute an
aspect-fit rect (scale to fit, centered) before drawing. Pure AppKit geometry, and
a natural home for a pixel-level test. 🚧 Implemented this pass.

### 🐛 K6 · P3 · 🆕 — `suggestedName` returns "1" for an IP-address site
`URLNormalizer.suggestedName(for:)` picks the label before the suffix. For
`192.168.1.1` the labels are all numeric, index lands on `"1"`, and the New Wrap
sheet suggests an app named **1**. **Fix:** when the candidate label is purely
numeric (an IP octet), fall back to the first label / the full host. Table-test it.
🚧 Implemented this pass.

### 🐛 K7 · P3 · 🆕 — ⌘G with the find bar hidden is dead, and its fallback is unreachable
`FindBarController.findNext/findPrevious` contain a deliberate fallback ("bar
hidden, field empty → use `lastQuery`"), but `SiteWindowController.validateMenuItem`
disables both items unless `findBar.isVisible` — so the fallback can never run.
Safari repeats the last search with ⌘G without reopening the bar. **Fix:** validate
on `isVisible || canRepeat` (a tiny exposed property). 🚧 Implemented this pass
(folded into the find-bar branch).

### 🐛 K8 · P3 · 🆕 — deprecated `activate(ignoringOtherApps:)` in the site runtime
`SiteAppDelegate.handleNotificationClick` calls
`NSApp.activate(ignoringOtherApps: true)`, deprecated in macOS 14 — a build warning
under Xcode 16. `UpdateChecker.runModal` already does the `#available(macOS 14)`
dance; copy it. **Note:** four open PRs (#6, #12, #13, #15) already touch
`SiteAppDelegate.swift`; deliberately *not* implemented this pass to avoid stacking
a fifth conflict on that file. Small, safe, and queued.

### 🐛 K9 · P3 · 🆕 — page zoom is per-session only (and a comment says otherwise)
`WrapBehavior.pageZoom`'s doc comment claims "⌘+/⌘− writes back to it". Nothing
writes back: `SiteWindowController.setZoom` sets `webView.pageZoom` and stops.
Relaunch and the zoom is gone; switch window and the new window is at the default
while the old one is zoomed. Two honest options: (a) persist per wrap in the site
app's own `UserDefaults` (runtime state, not configuration — the two-writer rule is
untouched), or (b) fix the comment. Related: ⌘0 "Actual Size" resets to 1.0 rather
than the wrap's configured default — defensible, but "reset to *my* default" is
what a wrap user means. P3 because K1 removes the actively-wrong half.

### 🐛 K10 · P3 · 🆕 — the style-resurrection observer watches the wrong node
`BoostScripts.applyStylesheet` installs a `MutationObserver` on
`document.documentElement` with `childList: true, subtree: false` to re-install the
boost `<style>` if the page removes it. But the style element lives in `<head>` —
one level deeper — so a SPA that clears or replaces *head's children* (framework
hydration, some meta-tag managers) removes the boost style without tripping the
observer. Only wholesale `<head>`/`<body>` replacement is caught. **Fix:** also
observe `document.head` when it exists (re-arming after `DOMContentLoaded` if it
didn't yet). Touches `BoostScripts` — coordinate with `RuntimeScriptTests`.

### 🐛 K11 · P3 · ✅ — corroborated backlog items (no action needed beyond it)
Verified accurate and correctly queued: notification clicks route to the front
window; minus button no-ops on shared boosts; "Delete Everywhere" lacks a confirm;
IDN hosts likely rejected; windows stack on one autosave frame; preview downloads
leak into the builder's Dock; session saved only at quit; find is hard-wired
case-insensitive; geolocation unsupported.

## 3. Performance

### ⚡ K12 · P2 · 🆕 — the builder Settings sheet shells out on the main actor
`BuilderSettingsView.task` calls `CodeSigner.availableSigningIdentities()`
(`security find-identity`, timeout 20 s) and `CodeSigner.isAvailable`
(`xcode-select -p`, timeout 10 s) — both synchronous `ProcessRunner.run` calls, and
`.task` inherits the view's main-actor context. Normally ~100 ms, but a wedged
`securityd` means the Settings sheet beachballs for up to 30 seconds. **Fix:**
`Task.detached` for the probes, assign back on the main actor. 🚧 Implemented this
pass.

### ⚡ K13 · P3 · 🆕 — session blobs live in `UserDefaults` and can reach ~24 MB
`SessionStore` keeps up to 12 windows × 2 MB of `interactionState` in the app
domain's defaults — a synchronous XPC write into cfprefsd at every quit (and per
the backlog's own P3, soon every 5 seconds). The file's own comment admits
"UserDefaults is the wrong place for megabytes". **Fix:** write one file per wrap
under the *site app's own* `~/Library/Application Support/<bundleIdentifier>/`
(not the shared `Wrapybara` folder — the session must stay private to the app).
Prerequisite for safe autosave-on-change; do them together.

### ⚡ K14 · P3 · 🆕 — every running wrap wakes on every wrap's publish
`ConfigurationWatcher` watches the shared `Runtime/` directory, so publishing wrap
A's config wakes wraps B…N, each of which re-reads and compares its own file
(small JSON, coalesced — cheap). At 12 running wraps × publish-all-on-launch it's a
dozen pointless wakeups a second. **Fix (later):** per-wrap subdirectories
(`Runtime/<uuid>/config.json`) so the directory watch is inherently scoped. Needs
a one-time migration read of the old flat path.

### ⚡ K15 · P3 · ✅ — corroborated and in flight / queued
Icon decode per render (PR #2), publish per keystroke (PR #3), no-op preview
applies (PR #11), `refreshStaleRuntimes` beachball, KVO-tick storms, response
buffering in the icon fetcher, unconditional `BoostMatcher.clearCache()` — all
verified real and correctly prioritised in the backlog.

## 4. Missing features

### ✨ K16 · P1 · ✅🚧 — a real error page for failed navigations
Backlog P1, and it earns it: offline launch = blank white window with an NSLog.
This pass implements it: a pure `SiteErrorPage` HTML builder (dark-mode aware,
carries the wrap's name, tint and the failed URL, escaped; **Try Again** re-issues
the navigation as a plain link activation, so it flows through `NavigationPolicy`
like any in-app click), shown for main-frame `NSURLErrorDomain` failures minus
cancellations and "frame load interrupted" (that's a download starting, not a
failure). Testable without a web view.

### ✨ K17 · P1 · ✅🚧 — loading state is observed but never shown
Backlog P1. This pass implements the minimum honest version: the toolbar's Reload
button becomes **Stop** (×) while `isLoading`, mirroring the View menu item that
already validates correctly. The deluxe thin progress bar stays in the backlog —
it wants `estimatedProgress` diffing (backlog ⚡P2) to land first anyway.

### ✨ K18 · P2 · ✅🚧 — boost presets on the shared shelf
Backlog P2 (glm 3.8). A handful of curated `Boost` values (Dark, Readable, Kill
Sticky Headers, Monospace Everything) behind an "Add Preset" menu in the boosts
footer, landing on the shared shelf switched off — exactly like an import, minus
the file. Pure values + a menu; nothing in the runtime changes. This pass
implements it, with the glm 4.7 empty-state copy fix folded in (same file, same
two lines).

### ✨ K19 · P2 · 🆕 — a match tester that accepts any URL
The Scope pane's "Does it match the home page?" line is the editor's best teaching
moment, and it stops one step short: you can't ask about the page you're actually
trying to scope (a settings subpage, a docs path). A small "test a URL" field under
it that runs `BoostMatcher.matches` live would close the loop. Pure matcher, one
`@State` string. Cheap and very much in the editor's spirit.

### ✨ K20 · P3 · 🆕 — inline enable toggle in the boosts list
Wrap-local boosts show a pause icon when disabled, but enabling/disabling requires
opening the editor and flipping the toolbar switch. The shared section already has
inline checkboxes — give wrap-local rows the same affordance (a checkbox bound to
`isEnabled`). One binding; saves the most common round-trip.

### ✨ K21 · P3 · 🆕 — icon preview at Dock sizes
The editor header shows the icon at 64 pt, where almost anything looks fine; icons
fail at 16 and 32 pt (illegible monograms, thin artwork). A small 16/32/64/128 pt
strip in the Site tab's Icon section would catch bad icons before the Dock does.
`model.icon(for:)` is cached after PR #2, so this is four `Image`s.

### ✨ K22 · P3 · 🆕 — "Copy Generated CSS" debug aid
`BoostCSSGenerator` is pure and the preview already shows *what* a boost does; a
small "Copy CSS" button (Code pane, next to the injection-time picker) that puts
the generated stylesheet on the pasteboard answers "what is this boost actually
emitting?" in one click — the same question the (larger, Phase 2) diff view
answers. Minutes of work, real debug value, zero runtime surface.

### ✨ K23 · P3 · 🆕 — "Open App" button on the build-success alert
The build alert shows the destination path and OK. When `launchAfterBuild` /
`revealAfterBuild` are off, that's a dead end — offer "Open" / "Reveal in Finder"
right there. Three lines in `LibraryModel.build`.

### ✨ K24 · P1 · ✅ — the big three stay queued
Drop/paste-a-URL to wrap (3.4), "Edit in Wrapybara" landing on the right wrap
(3.5), per-wrap storage clearing (3.6), `WKContentRuleList` blocker (3.7), undo in
the boost editor (3.9), PDF export (3.10) — all verified as still-missing and
correctly prioritised. (Drop-to-wrap note: sidebar/window drop is easy and honest;
*Dock-icon* drops of dragged URLs require declaring http(s) URL handling, which
would register Wrapybara as a browser candidate — the sidebar is the right scope.)

## 5. Visual issues & layout

### 🎨 K25 · P3 · 🆕 — the boost editor toolbar crowds at minimum width
Toggle + name field + 4-segment picker + preview button in a pane that can be
340 pt wide: the name field collapses to an ellipsis-sized sliver. The segmented
picker could become a toolbar-style icon picker (paintbrush / scissors / chevrons
/ scope) at narrow widths, or the pane min-width should rise ~40 pt.

### 🎨 K26 · P3 · 🆕 — the boost preview looks dead while loading
The preview status bar has reload/home/URL/pick, but no activity indication —
loading a heavy site looks frozen. `BoostPreviewController` already receives
`siteWebControllerDidChangeState`; an `@Published isLoading` + a small
`ProgressView` in the status bar is the whole fix. (Fold the backlog's "preview
downloads leak" quiet-mode into the same pass when someone picks it up.)

### 🎨 K27 · P3 · ✅ — corroborated
Transparent-title-bar top-inset handling (4.1), icon-only buttons without
accessibility labels (4.2 — grep confirms: `LibraryView` footer, `BoostsTabView`
footer, `BoostPreviewView` status bar, zap-list minus buttons), segmented tabs
(4.3), address-label affordances (4.4), brown picker overlay on brown sites (4.5),
"None yet" twice (4.7 — folded into K18's branch).

## 6. UX, convenience, delight

### 💡 K28 · P2 · 🆕 — the site app should notice when Wrapybara has moved on
A running wrap checks for its *configuration* changing but never learns that the
Wrapybara that built it has since shipped a newer runtime — the stale-runtime
badge only exists in the builder's library. One line in the site app's Settings
window ("Built by Wrapybara 1.0 — Wrapybara 1.2 is available") needs nothing but
the existing `UpdateChecker` pointed at the same repo. Closes the loop for users
who rebuild rarely.

### 💡 K29 · P3 · 🆕 — window-title zoom indicator
When zoom ≠ the configured default, Safari-style transient "125%" in the toolbar
would teach that zoom exists and per-session state is active (pairs with K9:
persistence makes the indicator honest rather than noisy).

### 💡 K30 · P3 · ✅ — delight backlog endorsed
Capybara easter egg (5.8 — the About panel deserves it), Wrapybara's own Dock
badge for stale wraps (5.7), template gallery (5.9), icon drag-out (5.10), wrap
health check (5.6), multi-select zap (5.5), CSS diff view (5.4), in-app boost
hotkeys (5.3). All still valid; none repeated here in detail.

## 7. Code health

- **K31 · P3 · 🆕** — `WrapEditorView`'s header comment promises drafts are
  "committed on submit and on focus loss"; the code commits on submit and on
  *disappear*. Clicking Build with an edited name still uses the old name. Either
  wire real focus-loss commit or fix the comment.
- **K32 · P3 · 🆕** — `confirmsQuitWithOpenTabs` counts *windows*
  (`windowControllers.count > 1`); its name and the alert copy say tabs. With
  native tabs, two tabs in one window gets no confirm. Rename or count tabbed
  windows.
- **K33 · P3 · 🆕** — `SiteMarkupParser.decodingEntities` handles named entities
  but not numeric ones (`&#x27;`, `&#38;`) — rare in `<head>` attributes, but
  `&#39;` is already there, so the table is halfway to pretending.
- **K34 · P3 · 🆕** — `importBoosts` does `Data(contentsOf:)` with no size cap;
  pointed at a multi-GB file it will faithfully try. A 1 MB ceiling matches
  `SiteIconFetcher`'s discipline.
- **K35 · P3 · 🆕** — three copies of `isRunningTests` remain (glm 6.4), plus the
  deprecation-dance helper (`#available(macOS 14) activate`) is about to exist in

## 9. What I'd tell the next reviewer to check first

Things I verified *enough* to list but not to run: the error page's behaviour on a
wrap whose boost aggressively recolours `html/body` (the error page deliberately
inherits boosts — usually lovely, worth one look); the stop/reload swap under
toolbar customisation (user removed the item → weak ref nil → fine, but look); and
K1's interaction with a wrap whose configured zoom is *changed in the editor* while
the app runs (the apply now propagates it — intended — one sanity check that it
feels like a feature, not a snap).
